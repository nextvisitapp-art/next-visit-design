The what and the how.

Tokens, primitives, and signature components — written as plain HTML/CSS Code Web can lift into either product. One pink ramp, one type system, one set of class names. Couples and Go consume from the same file.

How to use this docOne source of truth, two products

Every component below is written as a single .nv .foo block. Lift it directly. The styles depend only on the :root tokens at the top of this file — paste those into tokens.css and serve from both products.

Rules

  • Never hard-code a color in component CSS. Always reference a token.
  • Padding flexes by product (couples generous, go tight). Everything else is identical.
  • Class names use BEM-ish (block__elem, block--modifier). Stick to it.
  • State conveyed via ARIA attributes (aria-pressed, aria-selected, aria-busy) — not extra classes. Easier to keep accessible.
  • Phosphor icons via <i class="ph ph-name"></i>. Duotone reserved for category tiles only.

9 · PatternsHow the components compose

The couples Home hero — state machine

Replaces today’s three-stacked-pink-cards problem. One container, three states. Switch by saved-trip presence + date proximity.

StateWhenWhat renders
emptyno saved tripGentle empty card with single “Plan our next trip” CTA (see CouplesHomePreTrip)
upcomingtrip dated > todayCountdown component (see P-07)
livetrip dated within rangeCountdown variant with “Day 3 of 7” instead of “days to go” (build later)
arrivaltrip just saved from GoArrivalCard pinned above the countdown for 24h, then auto-dismisses

The Save → arrival choreography

The 4-frame sequence from the mockups. Implementation contract:

FrameSurfaceTriggerNotes
①go.next-visit.app/trip/:idresting state, bottom of trip detailHandoff card (.handoff) lives here permanently
②same page, bottom sheettap “Save to Next Visit”Anonymous-first: primary CTA “Open the trip”; email + checkbox below
③same page, sheet content swapafter submit (with or without email)Checkmark + “Open the trip” primary; passes trip JSON via URL hash
④next-visit.app/save-trip → /tap “Open the trip”Couples Home, ArrivalCard fades in, then countdown fades in 200ms later
Anonymous-first URL contract. Frame ③ → ④ passes the trip as #trip=<base64(JSON)> on the redirect URL. Couples Home reads the hash, persists to localStorage, and clears the hash. No email = no account; the trip lives on the device. Email = same flow plus a sign-in token POSTed to your existing auth endpoint.

10 · ImplementationPer product, per file

Couples · React/Vite SPA

  • Drop tokens at the top of src/styles/tokens.css; import once in main.tsx.
  • Each component becomes a React component with matching class names. Keep CSS modules or scoped CSS — class names stay the same.
  • The countdown component takes props for days, place, placeAccent, meta, actions, hearts. The body is identical in JSX to the markup above.
  • The Home hero state machine is one component switching on a derived tripStatus selector.
  • Arrival animation: framer-motion or plain CSS with @keyframes — respect prefers-reduced-motion.

Go · vanilla, single index.html

  • Drop tokens in a single <style> block at the top of index.html. Mirror the source of truth — no build step needed.
  • Replace today’s blue var with var(--pink-500) globally; the bulk of the rebrand is one search-replace on #0770e3.
  • Each affiliate card swaps from the current full-bleed colored div to .affil markup with an inline-styled monogram. Wholesale rewrite ~80 lines.
  • The countdown is currently rendered inline in trip-detail; lift to a single template literal so both variants (couples-style and go-style) share the same string with a conditional __photo prefix.
  • Keep document.fonts.ready guards around any FOUT-sensitive scripts that measure text.
